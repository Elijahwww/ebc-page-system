# EBC 文案可操作审稿量表 v0.1（基于真实案例，初始阈值待校准）

> 状态：RULE_CANDIDATE / RUBRIC_NOT_OUTCOME_VALIDATED。解决“克制、专业、用户导向”等词无法被模型准确执行的问题。
> 适用于每个独立文案单元（Hero H1+副标题+CTA 作为一组；单独模块标题+说明作为一组），**不能把分数当作实际转化率或客观审美真理**。
> 量表维度来自用户真实项目的多次审查及源码案例分析；下面的 0/1/2 分只是最初用于统一“为什么改”的编辑工具，随后应由用户的已确认案例继续校准。

## A. 先做五项否决项（任何一项 FAIL 则必须重写/压字/待核验）
1. `FACT_FAIL`：把尚未开放产品写成“立即交易”；错写公司/监管/产品/交易性质；无依据收益、费用、合作、杠杆、规模主张。
2. `USER_EXPECTATION_FAIL`：句子把 CFD 描述为实际拥有股票/ETF、将“参加/同步市场增长”引导为保证取得投资收益，或 CTA 与真实点击行为不符。
3. `SOURCE_STATUS_FAIL`：把 Claude 代码/历史上线/AI 草案误标“用户最终确认”；把过去审批无条件套到现今不同市场。
4. `CONTENT_JOB_FAIL`：无法说清这段文案具体回答的用户问题，或者与上下文完全重复，删掉对理解/行动毫无损失。
5. `LP_BLOAT_FAIL`（**v0.5 新增 · 仅适用于 `LP_PRODUCT` / `CAMPAIGN` 投放页**）：把投放页写成“产品说明书”——首屏左侧塞入超过 3 个元素（H1 + 副标题 + CTA）；单张卖点/优势卡写成多句长段落（超出 1 标题 + 1 短句 ≤ 16 字）；正文位嵌套科普墙、机制账本或 FAQ 手风琴；整页主文案明显突破 250–450 字预算；或直接把 PM 内部推演过程泄漏进页面 UI。**即使每句事实全部正确，触发本项也必须判 FAIL，强制执行一轮 Copy Compression（压字剪枝）**，同时在单行脚注中守住 CFD 性质与风险底线。

一票否决只表示 **当前稿件不应进入正式可发布内容源**，不禁止明确标记的研究假设或 Demo 占位。

## B. 8 个维度，0–2 分（每项必须附一行证据）

| 维度 | 0 分：需要重做 | 1 分：部分成立 | 2 分：达到当前编辑基准 | 来源与检查方法 |
|---|---|---|---|---|
| 1. 单一信息职责 | 句子主要是“共创、赋能、引领”等抽象表达，无法确定回答什么 | 有信息但混合多个主任务 | 可用一句具体话说明读者读完新增什么认知 | Careers/学院按用户作用命名；标题单一职责 |
| 2. 与上下文信息增量 | H1、副标题互为同义复述 | 部分重复但补了新信息 | H1 给结论/方向，副标题补机制/范围/条件；删一段会损失不同信息 | About 监管模块；Careers 开放职位 |
| 3. 可证据性与语义准确 | 无来源绝对化、产品性质被误导或动词改变真实权利 | 有来源但范围/单位/时态模糊 | 核心事实/产品名/条件准确；该写明的时间、对象、动作已写明 | Anthropic 状态；ETF “分享”；Old LP 股东/费用 |
| 4. 人群与入口适配 | 直接套错人群的知识深度或动机 | 部分适配，重要疑虑未解 | 文案回应目标人群的首要疑问，措辞与其熟悉的概念/度量一致 | Oil/Copy/ETF A/B/C |
| 5. 具体度与用户价值 | “卓越、领先、专业服务”无具体说明 | 有方向但用户无法理解机制 | 具体动作、产品功能、可查数据或职业价值构成主张锚点 | Careers 能力被认可→行动；Copy 风控模式 |
| 6. 可信/克制 | 虚假紧迫感、承诺确定性、自夸无依据 | 事实虽可用但表述夸张或条件缺失 | 陈述可核验且必要限定清楚；形容词有明确出处/用途 | ETF/原油夸张词；About 监管主体 |
| 7. 信息顺序与用户旅程 | CTA 前没有必要的产品理解或用户预期被误导 | 逻辑可懂但存在强跳转/遗漏 | 广告/入口→H1→下一段→行动按用户真实知识渐进，阻力被回应 | A/B 不同人群版本；Anthropic 待开放 |
| 8. 语言自然与功能匹配 | 生硬翻译、语义歧义、同义填充、按钮误导 | 可以读但冗余/抽象/拗口 | 中文表达自然、主宾/动词关系清楚、按钮用词与真实交互吻合 | ETF Banner “分享→同步”方向；Careers 按钮 |

`REVIEW_SCORE` = 合计（0–16），同时记录每项 0/1/2 与简短原因，**不是让模型给自己打一个无证据的 15/16。**

**初期编辑建议**：
- 任何 HARD FAIL 必须重写；
- 重要模块（Hero、交易机制、CTA）任何维度 0 都需要解释并修复；
- 总分仅用于比较同一项目同一用户任务下的两版，不设“13 分自动批准”的伪精密门槛；
- V2 必须针对 V1 至少一个可指出的问题真正改变内容；只有分数变高、字句不变不能算迭代；
- 同一文本跨人群使用应重新评分，而不是继承旧分数。

## C. 描述性词汇 → 可检查动作

| 模糊要求 | Agent 必须实际做什么 | 对应真实项目 |
|---|---|---|
| “专业” | 核对产品名、机制、数字、单位、边界；对熟练用户用可查交易条件而非行业空话 | Oil-B：0.01手/杠杆/时间；Anthropic CFD FAQ |
| “克制” | 标注删除的冗余或不可证明主张，保留真实的用户解释；不得把字数少作为唯一标准 | About “走进更多市场”被否；品牌数字需职责 |
| “不要说教” | 不直接对用户进行高姿态的“教育”，先识别其已知信息；已熟悉者少做入门科普 | ETF-B 删除重复长期收益教育，A/B 区分 |
| “有品牌感” | 用 EBC 可辨识的历史/能力/事实建立关系，而非“我们不断成长”过程流水账 | “始于伦敦，连接全球”方向 |
| “用户导向” | 写出用户读前的疑问和读后的正确答案，不能只写公司自我评价 | Careers/Copy A |
| “简洁” | 消灭重复信息；删一处后若重要信息丢失则不要删，优先把内容放回正确模块 | About 高密度监管/里程碑 |
| “有转化力” | 使主张与入口意图匹配，CTA 真实可执行；无数据不宣称 CVR 提升 | 3 主题受众版本与 CTA |
| “高级/Apple 风格” | 文案上具体表现为精准词义、主次信息、自然短句；不能抄 Apple 句型或素材 | 用户多次拒绝空洞 slogan |

## D. 不建议直接变成硬规则的“数字”
- 中文 H1 字数/双行必须与当前模块和目标语种有关。样本少且偏中文 LP，**不能以均值限制全部官网页面**。
- CTA 字数不能单独解释点击率。比字数更重要的是点击后实际发生什么。
- 每个模块出现几个数字不是质量指标；用户明确反感不具备叙事价值的 700+ 团队数字。
- “负面词汇黑名单”会误杀已确认的监管模块标题“国际顶级监管”。不能简单禁止“顶级”，而是判断适用上下文与证据。

## E. 验收记录示例（Careers）
文本：「在 EBC，让专业被看见，让想法成为行动。」
- 信息职责：候选人会获得怎样的工作价值，而非岗位筛选说明。
- H1/subtitle 分工：此句为 subtitle，必须与实际 Hero H1 联读后再判断重复；单独对其评分没有意义。
- 结构：专业被看见（获得认可）→ 想法成为行动（可落实）。
- 证据边界：用户在项目对话确认过这一文案，但并非提供了公司调研证明这些职业价值的真实员工数据。
- 修改测试：若将其改成“携手行业精英，共创卓越金融未来”，具体职业价值信息减少，因此 1、5 维应下降；**不造具体旧稿**。
