# 页面决策 v2

状态 WORKING_CANDIDATE。方案理由和模拟路径不是实际用户研究。

## 问题与策略

员工需要快速找到工作工具，同时保留集团公告和同事交流。现截图的主要视觉资源给了图文流与等级排行；四个业务工具缺少稳定入口。

| 策略 | 具体方式 | 代价与判断 |
|---|---|---|
| A 社区首屏加四个链接 | 复用现有瀑布流 | 最快，但工具用途、收藏、访问状态难扩展；仅适合过渡 |
| B 工作台 + 社区 + 应用中心 | 首页聚合常用工具和重要信息；社区独立保留 | 推荐。不同部门按自己的常用应用组织入口，后台业务由原系统承接 |
| C 所有工具重做为统一业务系统 | 翻译、活动、域名、素材全部复制 | 超出用户最新范围；已有工具架构未知，本轮不采用 |

对 B 最强的反例：非 MKT 员工可能只是读公告、看同事动态。修订：不放部门专用业务 KPI；保留重要公告和团队动态；允许个人选择默认进入社区。四个工具不占四项一级导航。

## 关键页面职责

| 模块 | 解决的用户问题 | 已实现安排 |
|---|---|---|
| 常用应用 | 去哪里开始工作？ | 首屏四卡，收藏、访问状态、负责人、详情 |
| 重要公告 | 现在需要知道什么？ | 首页三条，独立公告页可筛选与阅读 |
| 团队动态 | 其他团队在做什么？ | 图文卡片延续原平台分享体验，区分工作与生活 |
| 应用中心 | 有哪些工具可以用？ | 搜索、分类、收藏；打开/申请/建设中不同动作 |
| 个人信息 | 我的积分与习惯在哪里？ | 小卡片保留等级积分，时区和语言在个人页 |
| Board | 某月/地区有哪些活动？ | 复用附件真实记录，明确交付范围而非完成进度 |

## 用户路径（SIMULATION）

1. 海外非 MKT 员工：切英文 → 首页重要公告 → 阅读 → 返回。反例是中文图片无法被 UI 翻译；因此关键公告使用文字标题和正文，图片内容不承诺自动翻译。
2. 高频工具使用者：常用应用 → 详情/打开。反例是收藏被当成授权；因此收藏独立于权限，域名入口演示申请流程，申请记录在个人中心可见。
3. 活动同事：Board → 点击 11 月 → 选择 CN → 查看双 11 活动。反例是把交付勾选理解成已完成；因此卡片、指标、详情统一使用“交付范围”，不生成进度、逾期或负责人。

退出恢复：弹窗可关闭和 Esc 退出；列表提供清除筛选；本地发布、收藏、点赞与偏好刷新后保留。真实登录失效与跨系统失败由 IT 接口版实现。

## 文案审查

首页标题承担招呼/身份，副标题说明常用工具、公告和动态；不使用“一次登录，全部畅通”等未经证实的承诺。应用名称按任务命名。复用仓库 EBC-COPY-011（用户任务）、005（动作与去向）、007（状态变化）原则。

硬性核对：无虚构监管/收益、无真实后台或 SSO 已打通的宣称；Board 数字有附件来源；按钮动作符合实际演示。可读性、职责分工、可验证性、行动明确、语境匹配、重复控制、跨语言意义一致、状态一致八项逐项对照界面，英文短单位回退及手机溢出问题已在 QA 中修复。
