## 2026-11-12 · Claude 视觉重构 v2

执行者 Claude（Cowork，模型标识 claude-fable-5-2）；单 Agent。已实际运行 v1 与 v2，Playwright + Chromium 截图与交互回归；未做跨模型评审、真机或真实员工测试。分支 `projects/ebcshare-frontend-preview`（读取 `.git/HEAD` 确认），未触碰 main。

### 对 v1 的独立评估（基于 1440×900 与 390×844 实际渲染）

| # | 观察到的问题 | 影响 |
|---|---|---|
| 1 | 每个模块都是“白底 + 1px 边框 + 16px 圆角”的同款盒子，首页同屏十余个 | 没有主次，像后台模板而不是工作平台 |
| 2 | 字号集中在 11–18px，H1 30px，辅助文字低至 9–10px | 层级靠不出来，中文小字难读 |
| 3 | 酒红同时用于导航选中、按钮、标签、红点、进度条 | 强调色失去强调作用 |
| 4 | 应用卡只有小图标 + 两行字，四张几乎一样 | 最重要的入口没有辨识度，也没有可玩性 |
| 5 | Board 四个指标四个盒子，柱状图为浅粉无选中态对比 | 真实数据是全站最有内容的部分，却最平 |
| 6 | 右栏积分、最近使用、日历三张小卡堆叠 | 积分体验被压成一条细进度条 |
| 7 | 手机端表格横向滚动、弹窗居中小窗、底栏为贴边白条 | 窄屏像缩小的桌面版 |
| 8 | 关闭图标 SVG 路径写错（`M6 18 12-12` 画出屏幕外） | 关闭按钮显示为一条斜线 |
| 9 | 任意状态变化后整页重渲染，键盘焦点丢失 | 键盘用户每次点赞/筛选都要从头 Tab |

## 2026-11-12 · Claude v3：首页去重、视觉重做、时间与日历交互

执行者 Claude（Claude Code 桌面端，模型标识 claude-fable-5-2）；单 Agent。在用户本机 Windows 10 的内置浏览器实际运行并截图检查；未做跨模型评审、真机或真实员工测试。分支 `projects/ebcshare-frontend-preview`，未触碰 main。本机会话没有 git，改动未 commit。

### 用户对 v2 的反馈（原话要点）

1. 页面功能重复度太高：首页有常用应用，侧边又有快捷应用。
2. 视觉样式还可以加强，“AI 感太重”，需要有趣的交互和震撼的效果，请大胆优化。
3. 首页日历可以保留，但整体呈现太混乱、不够有趣。

### 过程中的修订

- 日月最初沿整幅天空的弧线运动，实测傍晚时月亮落在问候文字后面，像渲染错误。改为只在标题上方的带状区域运动、近地平线渐隐；手机端限制在右侧。
- 日月原在压暗层之下，显得灰蒙；调整层级到压暗层之上、文字之下。
- 首页公告与新鲜事最初等宽，新鲜事更高导致左侧留白；改为 1 : 1.45，新鲜事内部主推与紧凑行左右排。
- 浏览器缓存导致样式修改不生效，给 `styles.css` / `app.js` 加了 `?v=3.0`。

### 未改变的内容

路由、`localStorage` 键、原有 `dict` 词条的中英文、`data.js`、Board 口径、应用中心/团队动态/公告/看板/个人中心/翻译页的结构与功能。原有功能没有删除：收藏管理、成长记录、最近使用记录仍在，只是入口合并。

新增的交互（时间轴、日历点选与翻周、指令面板）超出了 2026-11-12 早些时候“功能无需增加”的范围，依据是用户本轮“需要一些有趣的交互…请大胆优化”。它们只读取已有数据，不新增业务数据或后台需求；是否保留由用户评审决定。
