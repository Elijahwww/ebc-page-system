# 02 跨案例分析（Cross-Case Analysis）

范围：CASE-001 ~ CASE-004（7 个推广页版本 + 1 个官网设计版本）。日期 2026-11-11。
标签：`OBS` 可直接观察；`INF` 推断；`NV` 待核实。所有结论均标注支撑案例。

---

## 1. 推广页的共同骨架（OBS，7/7 推广页版本）

```
Hero（H1 两行 + 一行副标题 + 单一主 CTA + 3D 产品主视觉）
 → 监管条（FCA / CIMA / ASIC / FSCA）
 → 产品解释 ①（为什么关心这个市场/产品）
 → 产品解释 ②（为什么用 CFD / 在 EBC 交易）
 → 信任（EBC 优势：工具 / 执行数据 / 监管 / 社区规模）
 → 品牌（巴萨、联合国基金会抗疟、牛津研讨会、CCTV 专访）
 → 三步开户（跟单页除外）
 → 版权（SVG 实体）+ 风险提示
 + 吸底/悬浮 CTA 条 + 全部 CTA → 同一个注册弹窗
```

- ETF 页（CASE-001）在第 4 屏插入"限时活动 + 倒计时"。
- 跟单页（CASE-003）无三步开户，用信号列表替代"产品解释 ②"。
- 官网页（CASE-004-D）结构不同：产品 Tab、主题化标的、报价表、FAQ、留资表单——**官网页承担信息完整性，推广页承担单一说服路径**（INF）。

## 2. A/B/C 人群版本到底改了什么（核心发现）

| 维度 | 小白版（A） | 专业/已有认知版（B / C） | 支撑 |
|---|---|---|---|
| H1 动机 | 身份化/门槛化："做全球巨头的小股东""一键参与""不会交易？" | 机会化/机制化："一个账户""油价每一次波动都是您的交易机会""跟随优质策略" | 001/002/003 |
| 第二屏认知任务 | 为什么要关心（ETF 长期收益、原油与生活、自己交易的困难） | 交易逻辑（国内 ETF 痛点对照、油价驱动因素、社区规模） | 001/002/003 |
| 度量单位 | 金额（10美金）、年化收益 | 手数（0.01手）、杠杆比（100:1）、交易时间、执行毫秒 | 002 |
| 信任证据 | 工具、监管、"简单" | 执行指标（87.6% / 0.0 pips / 20ms / 50+）、机制（MT 协议、风控） | 002/003 |
| 社会证明位置 | 靠后（先解决"我能不能用"） | 靠前（第 2 屏） | 003 |
| 活动露出 | 第 4 屏 | B：Hero 副标题 + 第 3 屏 | 001 |
| 删除的模块 | — | ETF-B 删除"长期收益教育" | 001 |

`INF` 版本差异不是"换标题"，而是**换首要动机、换对比对象、换度量单位、换信任证据、调整模块顺序**。这是本批资产中最有复用价值的方法论，3 个主题均成立。

`NV` 没有转化数据，无法判断哪种版本策略更有效。

## 6. 工程模式（OBS）

- 技术栈统一：Vue 3 `<script setup>` + Vike（SSG 预渲染，多语言路由）+ vue-i18n + Swiper。
- 每个推广页是一个独立的 Vike page 目录，页面级 locale + 公共 locale 合并。
- 注册弹窗逻辑（滚动锁定 + 滚动条补偿 + 触控/滚轮/键盘拦截）在 7 个页面中**逐页复制**（约 70 行），未抽象为组件。
- i18n key 两种风格：ETF 用序号 `word1…word49`（可读性差、跨版本序号漂移，如 C 版插入卡片后全部顺延）；原油/跟单用语义 key `s2C1Title`（更易维护）。
- 推断的开发顺序（INF，依据文件时间 + 脚手架残留方向）：ETF（2026-07）→ 跟单（2026-09-23）→ 原油（2026-09~10，复用跟单脚手架）。
- 脚手架复制残留：原油 locale 中的跟单 key、`copy-trading-page` class；usstocks 的 Affiliate 文案；ETF-B 未启用的 locale。
