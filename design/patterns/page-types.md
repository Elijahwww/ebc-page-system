# EBC 页面类型与视觉策略 v0.1

> 状态：DESIGN_BASELINE_CANDIDATE；历史案例索引见 sources/INDEX.md 与 asset-review/cases/CASE-00x.md（原始资源 PR #3）。
> 模块是候选信息职责，不是固定屏数或必选模块列表。优先按 PM Brief 选择。

## 所有页面首先决定 Header 类型
- 完整官网 Header：在适用市场按获批素材表现 EBC 主 Logo 与 FC Barcelona 合作标识；详见 [Header 与品牌标识规范](header-brand-and-partnership.md)。
- 精简 LP Header：EBC 主 Logo 优先，FC Barcelona 合作标识是否展示按渠道、市场和授权判断，不预设全站强制。
- 无 Header：用户指定无头无尾的设计任务或特殊嵌入式页面可省略，并在项目级 Design Override 说明。
- 当前历史源码只提供 topMenuNoA 的调用，没有共享组件实现，不能用它推定正式 Header 的图形和尺寸。

## A. 官网品牌页（Corporate / About / Careers）
目标：帮助访问者迅速理解公司是什么、能提供什么、有什么可核验的可信证据，以及下一步去哪里。
- Apple-inspired：明亮背景、专业排版、宽松留白、真实团队/办公/产品影像、有限品牌红强调。
- 常见模块：简洁 Hero → 事实/监管（市场实体准确）→ 核心能力 → 人物/实证 → 联系/下一步。
- 页面内容可以长于 3–4 屏，前提是每个模块有独立信息职责。真实里程碑优于花哨时间线。
- 招聘页可用职位列表/岗位地区筛选/投递弹窗，不能强行套交易 CTA。
- 避免内容：空洞品牌口号、编造里程碑、假照片、把监管 logo 当作全集团所有市场许可的证明。

## B. 官网产品页（Product / Trading）
目标：对产品建立准确理解和可执行的下一步，而不仅是促成点击。
- 视觉：产品图/真实平台 UI/规格数据主导；数据表、FAQ、风险/产品条件易读；少使用无关 3D。
- 建议模块：Hero 产品定义 → 对用户意味着什么 → 产品机制/条件/示例 → 交易平台或代码/报价 → FAQ → CTA。
- 报价、杠杆、费率、交易时段有真实产品/实体/时间限制；未经核准不要用品牌视觉替代说明。
- 官网页面有 SEO、可访问语义结构与多语言长内容要求。
- 本批 US-D 仅设计稿，X-usstocks-code 另属可能不相干页面，不能作为已完成产品页工程模板。

## C. 广告落地页（Performance / SEM / Social）
目标：让对应流量的用户快速理解广告承诺与实际产品，再进入合法有效的转化动作。
- 每个 LP 按市场、渠道、用户认知程度和投放目标选择 Hero 说服点；保证广告 → 首屏一致。
- 常见模式：Hero 清楚讲一件事 → 用户相关性/机制 → 可核验卖点与条件 → 信任 → 明确下一步 → 必要风险/隐私信息。
- A/B/C 历史跨案例观察：变化不止 H1，还涉及动机、对比对象、数字单位、证据与模块顺序。**无转化对照，不保证任何版本最优。**
- 单页可有重复主 CTA，但同视野信息主次清楚；Sticky CTA 按渠道/设备启用，不能遮挡正文。
- 允许更浓重的视觉和深色 Hero（仍保留 EBC 品牌、可读性和事实准确性）；不要一律复制旧项目的酒红 3D hero。
- 不强制 H1 两行、每屏数字、3–4 屏或固定注册弹窗。具体表单方式由 PM/CRM 已批准方案决定。

## D. 活动页（Contest / Promotion / Enrollment）
目标：让用户理解资格、时间、参与方式、规则、奖励和参与结果。
- 关键模块：活动价值 → 资格/规则 → 时间/状态 → 流程/奖项/榜单（适用时） → CTA → FAQ/法律条款。
- 时间倒计时、活动费用优惠必须有有效期与到期后状态；过期不能只隐藏计时器而继续展示优惠承诺。
- 不得伪造排名、报名人数、预计收益。示例数据必须标注 Demo。
- 游戏化不能凌驾于信息可核验和风险透明之上。

## 页面级 Design Override（每次任务至少说明）
- Type: 官网品牌 / 官网产品 / Performance LP / 活动
- User: 市场、国家、受众、经验、设备和主要语言
- Conversion: 主要 CTA 文案、真实目标、是否使用表单/Portal
- Style: 明亮默认；若深色 Hero/全暗色需注明原因
- Media: 真实素材/授权来源/缺图占位及适用区域
- Constraints: 合规、SEO、多语言、可访问性、性能和上线状态
- Differences: 对全局 token/组件/响应式的项目级修改与依据

## 旧版案例不能覆盖用户当前需求
- 旧推广页的通用结构/按钮/红色 token 是历史观察。
- 当前项目已确定的文案、真实参数、产品状态与法人实体优先。
- 风险提示与法定披露绝不可为了通过广告审核或视觉好看而隐藏。
