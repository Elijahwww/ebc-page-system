# Web Design System · 基础与详细规范 v0.1

> 状态：DESIGN_BASELINE_CANDIDATE。以下**数值由 EBC 本项目提出**，不是 Apple 官方网页 CSS 参数；Apple HIG 更多面向平台 UI 的原则。
> 默认：桌面与移动端均完整设计；一切数值以 CSS px 为单位，适当使用 rem、clamp、% 和容器查询。

## 1. 设计哲学（APPLE_OFFICIAL_PRINCIPLE → EBC 解释）
1. Simplicity：减少无意义装饰，但不要为了“极简”删掉理解金融产品所需的信息。
2. Hierarchy：每个模块的标题只承担一个主信息任务；优先传达用户能理解的价值和下一步。
3. Craft：精确排版、稳定图片、对齐、状态细节、真正可用的交互。
4. Inclusive & adaptive：不同尺寸、输入方式、文字长度/语种下保持信息可用。
5. Product first：产品/市场数据真实、显著条件与风险清晰，视觉不得制造虚假收益确定性。

## 2. 布局与栅格（EBC_PROPOSED_TOKEN）
| Viewport | 结构 | 内容版心 | 左右安全边距 | 推荐列/间距 |
|---|---|---|---|---|
| ≥ 1200 | desktop | 常规 1200；品牌视觉可到 1280 | 40–64 | 12 列 / 24 |
| 768–1199 | tablet | 宽度减边距 | 32 | 8 列 / 20 |
| 360–767 | mobile | 宽度减边距 | 20（最小 16） | 4 列 / 16 |
| < 360 | narrow | 优先保证可阅读与不横向滚动 | ≥16 | 单列优先 |

- 全幅背景可满宽，但**核心文字、CTA、表单不得溢出版心**。
- 默认正文栏宽 640–760；长中文/英文段落不要横跨 1200 px。
- 多列卡片：桌面 2/3/4 列视内容密度选；平板 2 列；手机通常 1 列。不可为维持原卡片数缩小文字。
- QA 视口至少覆盖 360、390、768、1024、1440、1920；断点可按内容需要调整，不强制历史 996px。
- 禁止通过全站 vw-rem 等比缩放导致超宽屏字体过大或低分辨率字体过小；推荐 fluid clamp 与现代栅格布局。
- 页面应允许 200% 缩放、语言扩展而不遮挡关键功能。

## 3. Typography（EBC_PROPOSED_TOKEN）
| 角色 | Desktop 推荐 | Mobile 推荐 | 行高 | 字重 |
|---|---|---|---|---|
| Display / 大 Hero | clamp(48px, 5vw, 76px) | clamp(34px, 9vw, 44px) | 1.08–1.18 | 600–700 |
| Hero（营销 LP 较紧凑） | clamp(42px, 4.2vw, 64px) | 32–40 | 1.12–1.2 | 600–700 |
| Section H2 | clamp(34px, 3.3vw, 52px) | 28–36 | 1.15–1.25 | 600–700 |
| Card H3 | 24–30 | 20–24 | 1.25–1.35 | 600 |
| Lead / 说明 | 18–22 | 16–18 | 1.45–1.6 | 400–500 |
| Body | 16–18 | 16 | 1.55–1.75 | 400 |
| Label / Meta | 14–16 | 14 | 1.4–1.6 | 500 |
| Fine print / 风险说明 | 13–14；长段建议 14 | ≥13，优先 14 | ≥1.55 | 400 |

- 字体栈优先 system-ui、-apple-system、BlinkMacSystemFont、Segoe UI、PingFang SC、Microsoft YaHei、Noto Sans CJK SC、sans-serif。日/韩语按实际 font fallback 检查。
- 不将 Apple SF Pro 字体文件拷贝/打包给网页；使用合法可用字体。
- 容易理解的排版优于强制 H1 换行。只有单个主要 H1，且不得仅靠 CSS 伪元素表达重要文案。
- 避免极端紧字距。英文显示标题可轻微负 tracking（约 -0.02em）；正文默认正常；中文长段不强制负字距。
- 左对齐适用于信息较多的模块；居中适用于短 Hero，不用整页居中装饰。
- 具体语言文本优先检查：中文、英文、西语、葡语、泰语、日语、哈萨克语等长词/断行；不能依靠隐藏文本避免溢出。

## 4. Spacing / rhythm（EBC_PROPOSED_TOKEN）
- 4px 为基础增量：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96 / 128。
- 标题—描述：12–24；描述—CTA：24–36；标题—模块内容：32–56。
- 页面模块垂直留白：桌面一般 96–144；手机 64–88；信息密集模块可更紧凑。
- 卡片内部：桌面 24–40；手机 20–24。卡片相邻间距：16–24。
- Hero 垂直留白由标题/媒体比例决定，常见桌面 88–144、手机 64–96；不要固定首屏高度导致重要 CTA 被遮挡。
- 视觉大片留白须有节奏，**不是越空越高端**。金融信息需兼顾用户理解与信任。

## 5. 色彩与层级（EBC_PROPOSED_TOKEN + EBC_HISTORICAL_OBSERVATION）
建议浅色基线：背景 #FFFFFF；浅灰舞台 #F5F5F7；正文 #1D1D1F；次级正文 #6E6E73；弱边框 #D2D2D7。特殊页面允许暗色视觉模块，确保对比与品牌一致。
- EBC 红 #A52933（历史 CSS 共见，非品牌手册审批）作为主要 CTA 候选；hover #8D212B；pressed #6E1722。
- 白色文字置于 #A52933 计算对比约 7.08:1，适合主要 CTA；不可照搬历史亮红 #FF4B4E 作白字小号按钮（白字对比约 3.30:1，不满足一般文本 AA）。
- 亮红可以作大面积视觉装饰或在满足对比度的文本搭配下使用，**不要把“历史见过”当作批准全局按钮规范**。
- 强调色一次只突出真正关键的行动/数据。涨跌配色需按地域习惯考虑，但数字、符号和文本标签必须同步呈现；不能仅用红绿区分涨跌。
- 不同市场/实体、合规风险信息不通过灰到不可读的颜色隐去。

## 6. 组件规格（EBC_PROPOSED_TOKEN）
| 组件 | 默认尺寸和表现 | 必要行为 |
|---|---|---|
| Primary button | 高度 ≥48；左右 24–32；圆角 999（胶囊）或 12–16 | hover、active、focus-visible、loading、disabled、链接/注册错误 |
| Secondary button | 高度 ≥44；描边/纯文字区分层级 | 与 Primary 视觉层级明显，目标清晰 |
| Text link | 字号 ≥14，推荐 16 | 文案能说明目的，hover/underline/focus，可键盘访问 |
| Input / select | 高度 ≥48；边框 1–2；圆角 12 | label、helper、error、invalid、focus、auto-complete |
| Card | 圆角 16–24；内边距 24–40/20–24 | 不默认一切卡片可点击，点击时提供 hover/focus |
| Modal / Drawer | 最大宽度按内容 480–640；移动端保留 16–20 边距 | ESC / Close、焦点管理、遮罩、滚动、失败恢复 |
| Tab / FAQ | 触控目标 ≥44，内容高度自适应 | 活动态可识别，键盘可操作，正确 aria 属性 |
| Sticky CTA | 仅符合用户任务时启用；手机避开系统底部安全区 | 不遮挡风险/表单/隐私弹层，适合页面类型 |
| Metric / quote | 数字+单位+来源+条件，重要数据标示更新时间 | 不能将模拟数字伪装真实行情或保证收益 |

- **建议目标触控区域 ≥44×44 CSS px**（本项目比 WCAG 2.2 AA 的一般最小 24×24 CSS px 要求更宽松/更易触控，不要把这两个数混同）。
- 同视野最多 1 个视觉主 CTA，次要动作明确降权；并不是“整页只能一个 CTA”。
- 组件可以自建；暂不依赖 EBC 旧共享组件，之后在真实前端验证再接入。
- 金融业务表单必须先确认字段、合规同意、CRM 接口与数据隐私要求；Demo 可用非生产占位并明确状态。

## 7. 图像与主视觉（EBC_PROPOSED_TOKEN）
- 优先真实、授权、与模块意义相关的摄影/产品 UI 截图，不用一组无意义 3D 球体/玻璃卡替代用户信息。
- Hero 至少说明“产品是什么/为什么值得了解/下一步”；主视觉不要压过内容职责。
- 使用响应式裁切/picture/srcset/现代压缩图，保留 focal point；PC/MB 可有独立素材，不靠缩小桌面图解决移动端。
- 图片 alt 描述内容，纯装饰图使用空 alt；任何图中数字/金融声明应有可阅读的文本与来源。
- 巴萨球员、Apple 商标、第三方品牌/人物素材的使用须遵守授权；不可直接复用 Apple 页面图片。
- 风险/监管/奖励/交易数据必须来自已批准内容源；无法核实时使用明确的 Demo 占位，不编造。

## 8. Motion / feedback（EBC_PROPOSED_TOKEN）
- 微交互：120–180ms；常规状态/卡片：180–280ms；模块进入：300–500ms；建议 ease cubic-bezier(0.2, 0.8, 0.2, 1)。
- 动画的职责是帮助感知状态、引导视线，不是整页滚动炫技。避免长时间自动轮播/大量视差和阻断滚动。
- 尊重 prefers-reduced-motion：移除非必要运动；动效结束后仍要保证内容可读。
- 加载、成功、失败、空状态均需反馈；交互状态不只靠颜色区分。
- 视频若自动播放须静音、可暂停，并提供合适的封面/降级；不可因此阻断关键文字。

## 9. Web 可访问性与性能（W3C_WEB_REQUIREMENT + EBC 推荐）
- WCAG 2.2 AA 基准：一般文本对比 ≥4.5:1，大字（≥24px 常规或 ≥18.66px 粗体等价）≥3:1；关键 UI 控件/图形对比 ≥3:1（以适用成功准则为准）。
- WCAG 2.2 AA 指针目标原则上 ≥24×24 CSS px 或符合间距/例外；EBC 推荐 ≥44×44 CSS px。
- 保留明显 :focus-visible，避免焦点被吸顶导航、悬浮 CTA 等遮盖；所有 CTA/表单/FAQ 键盘可用。
- 支持文字放大、表单错误恢复、语义化 H1/H2、正确 lang、输入 label 和可访问提示。
- 优化首屏媒体体积、LCP、CLS、加载优先级；不把历史“首屏 2–4 秒”作为已批准性能 SLA。
- 禁止在前端源码中暴露私密 API 密钥或长期内部访问 Token。

## 10. 页面级例外与审批
每次设计开始写明：页面类型、目标市场/语言、批准文案版本、主要 CTA、是否允许深色 Hero、Hero 资产来源、是否有 Sticky CTA、特殊合规/风控信息。
与默认基线冲突时，输出一份 Design Override：改哪条、为什么、适用哪些页面、对可访问性和维护有什么影响、谁确认。
**本文件是设计默认值，不是由单个历史案例推断出的公司强制规范。**
