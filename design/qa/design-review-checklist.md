# Design QA / 交付检查 v0.1

> 状态：DESIGN_BASELINE_CANDIDATE。审核每项标记 PASS / FAIL / N-A / TO_CONFIRM；记录证据、责任人与修正优先级。与 PM G2–G5 检查联动。

## A. 输入与方向
- [ ] 已识别页面类型、受众、主要市场与语言、渠道、主 CTA 及目标去向
- [ ] 使用获批文案/业务数据；没有把历史案例或 AI 构思当成当前公司事实
- [ ] 每个模块有独立信息职责，无纯填充屏
- [ ] 设计风格借鉴 Apple 的清晰层级与节奏，保留 EBC 自身品牌；未复制 Apple 素材

## B. 排版与布局
- [ ] 容器宽度、间距、列数符合本次项目 Design Override 或默认规范
- [ ] 主信息层级明确，正文/脚注不因“高级感”而过小
- [ ] Hero 图文权重合理，CTA 明显、可达
- [ ] PC 与 MB 的内容顺序可用；无横向滚动、文字覆盖或图片焦点丢失
- [ ] 不强制 H1 两行、3D 视觉或固定屏数；实际选型可解释
- [ ] 测试 360 / 390 / 768 / 1024 / 1440 / 1920 视口和 200% 缩放

## C. 组件与交互
- [ ] 按钮、输入、菜单、弹窗、Tab、FAQ（适用时）有 hover/active/focus/disabled/error/loading 状态
- [ ] 建议点击目标 ≥44×44 CSS px；适用 WCAG 2.2 AA 的 24×24 最低要求及例外
- [ ] 键盘路径完整，焦点顺序与屏幕阅读器标签正确；Esc/关闭与返回行为合理
- [ ] Sticky CTA / modal 不遮挡主要内容与风险/隐私信息
- [ ] 动效不影响理解或性能，尊重 prefers-reduced-motion

## D. 多语言与视觉资产
- [ ] 长语言文本无剪裁，字体覆盖对应文字，动态数字/单位不乱序
- [ ] 图片具备合法授权、清晰焦点，使用 PC/MB 合适裁切
- [ ] 数据、图表、统计数字有清晰来源/日期/适用市场，非实时数据不可伪装为实时
- [ ] 图中文字可替代，重要信息不可只有图片
- [ ] 不使用未获得许可的 Apple 专有资产/字体文件

## E. 可访问性与开发可实现性
- [ ] 普通文字对比 ≥4.5:1；大号文字 ≥3:1；适用的 UI 非文字对比符合 WCAG 2.2 AA
- [ ] CTA/输入正确 label，阅读顺序语义清晰，焦点可见且不被遮挡
- [ ] 响应式使用 clamp/grid/flex/container query 等适当方案；不以全局 vw-rem 缩放掩盖布局问题
- [ ] 性能图片压缩/懒加载/首屏加载优先级合理，没有无意义大视频造成阻塞
- [ ] 设计规范能映射到 CSS token/组件状态，交接中无“请自行发挥”式关键缺口

## F. 金融品牌与业务检查
- [ ] 监管主体、产品性质、费率、收益/业绩及适用资格不因设计改变原意
- [ ] 风险说明邻近相关数字且可读；不为了通过投放审核而删除必要披露
- [ ] 未经批准的产品或活动，视觉/CTA 不暗示“现已开放”
- [ ] 不允许将 Demo/mock 行情、信号、收益或品牌数据伪装真实

## 交付包
1. Desktop & Mobile 布局，关键响应式例外；
2. 颜色/字体/间距/按钮等项目级 tokens 与偏离原因；
3. 组件状态表和交互说明；
4. 素材及授权/占位清单；
5. 设计 QA 结果与待确认问题；
6. 能交给 Claude Code 的实现约束清单。
