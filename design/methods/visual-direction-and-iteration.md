# EBC · 视觉方向、反模板化审查与代码迭代 v0.2

> 状态：PROPOSED_GLOBAL_WORKFLOW / 2026-11-12。跨公司官网、产品页、LP、Campaign、活动、平台/工具页面使用。**它是审美/实现方法，不是某个页面类型的固定视觉皮肤或模块表。**
> 设计输入遵从 `AGENTS.md`、已确认中文 Copy Sheet、目标市场和项目用户反馈；不因为想更“好看”而私改已批准业务事实。

## 为什么新增
旧 Design v0.1 写清了栅格、字体、间距、可访问性，但没有明确的**设计方向选择 → 排除模板默认值 → 真实渲染视觉批评 → 实质重构**循环。功能 QA 全 PASS 仍可能存在拥挤、同质卡片、无辨识度或审美偏题。外部参照为 [开源研究](../research/ai-coding-visual-skills-2026-11-12.md) 与 [用户 Figma Make SKILL 提取](../research/user-figma-make-skill-analysis-2026-11-12.md)。

## 0. 分开三类约束，不能相互替代
- **事实与内容**：PM 目的、已确认的中文文案、用户任务、CTA、产品真实状态、监管/数据；由相应来源锁定，视觉不能删除。
- **审美方向**：用户明确给定的“干净、科技感、克制、酷炫、活泼”等调性；如矛盾或缺细节，优先通过探索和对比提出工作解释，不自封为用户批准的风格。
- **技术质量**：响应式、键盘与可访问性、交互状态、性能、代码可运行；单独 QA。代码能跑不代表审美通过。

## 1. 输入确认与页面模式
用 5 行以内的 Art Direction Brief 识别：
1. 谁在什么场景使用、页面要解决的首要问题；
2. 渠道/市场/移动优先级/目标语言（默认中文工作语言≠中国市场）；
3. 用户的审美关键词 + **不能接受的视觉**（negative references）；
4. 当前信息密度（少/中/高）、阅读路径与交互频次；
5. 授权素材、品牌约束、代码环境、现有页面 v1 截图和已确认文案。

先区分页面**行为模式**而非简单行业标签：
- **Persuade**：广告/产品宣传/活动参与，重点是叙事、注意力、有效证据和明确行动。
- **Operate**：工作台/系统/工具，重点是高频任务、可扫描性、导航与状态；不等于传统 ERP 视觉。少量标志性界面表达可以提升趣味，但不能牺牲操作。
- **Read**：学院、FAQ、解释型内容，重点是阅读节奏和事实。
- **Experience**：图库、故事、活动展示，视觉和内容本身是体验。
这些只是思考框架，混合页面需要明确主次；不能把某种固定 UI 模板强加给模式。

## 2. 先设计方向，再编码（ART_DIRECTION_GATE）
在重构或新建高影响页面之前，提出 **2 个真正不同的视觉策略**（QUICK 小修可给 1 个 + 反例），每个包含：
- **一句核心视觉命题**：例如“以有辨识度的工作入口为主角，其余资讯收束为安静背景”，避免“高端、专业、现代”抽象词。
- **具体的版式思路**：首屏哪块最强、哪些折叠、疏密如何交替；可以用小线框/ASCII。
- **主要视觉语言**：背景/表面/字体个性/强调色的职责/媒体与插画/空间密度/圆角和线条/动效入口。
- **该方向为何适合真实用户与当前产品，而不适合任何陌生项目**。
- **被拒方向及原因**：为什么不是统一白卡、暖纸+衬线、科技蓝渐变、玻璃背景、营销大数字等默认？这些风格并非永久禁用，但必须有针对本项目的理由。
- **保留不变**：项目功能、产品事实、Copy IDs、已确认 CTA 和交互。
用户已明确指定视觉方向时直接服从，并用备选/反证服务该方向，不再让模型擅自改成它喜欢的风格。审美方案是候选，可以做小样而不必强制人工批准每张中间图。

## 3. 信息层级不是把字体统一做大
- 一个视野范围中应存在清晰的**主角 / 次级支持 / 背景**；相同尺寸、相同背景、相同边框的 10 张卡不是信息架构。
- 先用内容职责合并、分组、折叠和按需展开降低密度，再调整卡片 padding。**不要为显得空而删除真实必要的金融、资格和风险信息。**
- 一种组件的视觉权重应与它在用户路径上的任务匹配；积分、榜单和动态不是每个页面都要做视觉主角。
- 视觉应有可证明的阅读次序：入口 → 用户关键问题/任务 → 证据或辅助信息 → 下一动作。
- 模块之间轮换 **密度、尺度、主媒体、颜色场景或空白**，但保持统一的整体语法；不是每屏必须换背景色。
- 位置、边界、标签、数字、icon、序号只在编码有用信息时使用；不习惯性加“01/02/03”、全部大写 eyebrow、小灰标签、“→”装饰。

## 4. 视觉原创性与防 AI 模板检查（AESTHETIC_SPECIFICITY_GATE）
检查能否把 EBC 名称换成另一个完全无关品牌而几乎没有变化；若能，应找出当前项目真实对象、互动任务、独特证据或真实素材进行改造。
常见待解释的默认值（不是全局禁令）：
- 同尺寸白卡/同圆角/同灰边框、卡片里再套卡片、无层级的 KPI 四连卡；
- 暖米白 + 强衬线 + 陶土点缀、黑底荧光绿、模糊蓝紫渐变、赛博网格、随意玻璃拟态；
- 每屏完全一样的标题居中 + 三张卡；通用 3D 球体/数字堆砌；只有装饰没有产品含义的图片；
- 每张卡都有微动画、每屏同款 fade-up；过多悬浮 CTA 与重复动效。
**不强制“必须使用特殊字体/3D/WebGL/深色科技风”**。克制也是一种强设计，前提是层级与构图有意识、素材真实、细节精确。

## 5. 执行：结构与品牌保持一致，表达可大胆
- 使用 `design/foundations/` 的语义 tokens 作起点，必要时建立**项目级 Design Override**：例如更冷的科技舞台、更大胆字体尺度、不同卡片比例；说明这些选择的阅读与品牌理由。
- 字体必须检查中英文和 Windows/macOS 的真实回退；不要因为 GitHub 高星 Skill 说“禁用 Inter”就禁止合法、可读、适配 EBC 的 Inter / 系统字体。
- 金融数字/真实客户/用户数据要标真实性，不为炫目生成无出处仪表板。
- Motion 使用一两个有意图的**标志性动效时刻** + 交互反馈，交互有因果、可中断，尊重 reduced-motion；不强制引入 React Bits、WebGL 或任何依赖。
- 素材优先真实可授权的 EBC/产品图片、实际 UI、可验证数据或为该项目专门构思的中性原创图形；**不能把一张通用抽象图片当作“主视觉”证据**。
- 现有页面「视觉重构」允许重排视觉层级、字体、组件结构，受保护的事实、业务动作与确认稿保持不变；「小范围润色」不得重写整个身份。

## 6. 真实渲染闭环（RENDER → CRITIQUE → REVISE）
必须针对**实际运行代码**而不是代码猜想做视觉评估，工具不足时标 `VISUAL_QA_PENDING`：
1. **运行 / 截屏**：对目标桌面和移动端实际渲染；至少获取 Desktop 首屏、Desktop 全页或关键页面、Mobile 首屏及关键交互状态。多页面项目需抽样所有不同结构类型。
2. **两种审查分开**：
   - **Visual Critique**：方向符合 Brief 吗？哪个部分先被看见？哪里显得拥挤/平/假科技/模板？是否使用真实产品元素？移动端是否重新组织？
   - **Engineering Audit**：响应式、溢出、可访问性、交互状态、性能、i18n、Console。工程 PASS 不得写成视觉 PASS。
3. **优先级**：P0 用户任务/事实损坏；P1 视觉方向严重偏题或首屏/关键路径层级失败；P2 局部对齐、字体/信息密度、弱可读性；P3 精细润色。
4. **产生实际修改**：每次指出“截图区域/问题 → 原因 → 更好的设计选择 → 修改的代码/Token → 新截图可见的差异”，不能只报告自评通过。
5. **二次复核**：新旧截图并排比较；若仍然无明显审美提升或方向偏题，回到第 2 步重新选方向，不反复微调同款卡片。
6. **真实用户判断**：用户明确说“不好看/不够科技/太挤”时，视为**未通过视觉评审**；不以 30 项功能测试通过抵消用户审美否定。
7. 最终明确 `VISUAL_REVIEW_READY`（供用户评审）与 `VISUAL_USER_APPROVED`（用户明确认可）不同。无浏览器则不得声称截图审查完成；无真实部署不得声称线上已更新。

## 7. 每轮交付的最小证据
- Art Direction Brief + 主要视觉选择（含一条被拒替代）；
- 是否偏离基础 Token、为什么；
- 实际设计/代码地址与所用 Copy Sheet 版本；
- Desktop/Mobile 真实截图位置、浏览器/视口（或标 PENDING）；
- Visual Critique Top 3、实际修复列表、V1→V2 对比；
- Engineering QA 的已测/未测范围；
- 需要用户决定的真正审美分叉，更新项目 `iterations.md` / `handoff.md`。
不制造繁琐的大报告；重点是给用户**可运行的、确实改进的设计**。

## 8. 何时升级规则而不是只修当前页
若「统一卡片堆满首屏」「用动画掩盖弱内容」「布局层级不足」「视觉方向与 brief 偏离」在多页面反复出现，可将机制提升全局规范。某个 EBC Share 页面选用冷黑/暖纸/衬线或其反例，只作为项目历史，不自动约束官网 LP。
