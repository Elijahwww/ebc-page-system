# EBC PM 思考引擎 v1.0：不是流水线，而是可回退的审查网络

状态：CORE_WORKFLOW_CANDIDATE（用户明确提出第一期就需要深度循环）；非公司正式 SOP。
作用：面向官网、产品页、投放 LP、活动页的需求、研究、心理路径、文案、方案质量控制。设计/开发为后续执行层，不主导本流程。

## 任务语言与市场的两个独立变量
- 默认 `working_language=zh-CN`：PM 五节点工作产物及中文主稿先定稿，再安排独立本地化任务。
- `target_market` 绝不能因为中文输出而默认 China；针对日本等明确的区域市场，D/R/U/S 从起点加载当地规范/当地外部参考后再以中文形成策略，不能把中国用户心理路径翻译成其他市场。
- 页面结构/视觉/开发组件以通用系统为基线，只有确有地区特异性时采用局部 Override。
- 详见 `localization/chinese-first-and-market-overrides.md`，不要让翻译工作提前拖慢中文 PM 文案确认。

## 核心目标与先后关系

PM Agent 的目标不是尽快输出页面，而是不断减少“错误问题、错误用户、错误说法、错误路径、错误结构”带来的返工。任何节点发现新证据，都有权撤销已形成的临时结论，跳回前置节点。

起始问题可以来自用户的一句话、需求邮件、截图或已有页面。Agent 先从已有材料抽取有效信息，不要求用户重填一套表。

五个思考工作台（NOT A ONE-WAY PIPELINE）：
- D / Demand：需求重构与反证
- R / Research：行业、竞品、市场、用户证据
- U / User：决策心理、前后场景、路径分叉与失败模拟
- C / Copy：文字的理解力、可信度、差异化与说服力
- S / Strategy：结构证据优先、模块准入、CTA 旅程、两种真正不同策略的取舍与纠错；不为凑不同模块数强制加屏

建议依赖图：
D ↔ R ↔ U ↔ C ↔ S；其中任何工作台发现矛盾都返回相应上游。C 的文案可改变 U 的预期，U 的新疑虑可能重做 R，S 的信息结构可反推 D 的目标。

## 每个工作台必须执行一次完整的评审循环

1. DEFINE：针对本轮定义具体决策问题（不是“研究竞品”这种泛任务）。
2. DRAFT：形成可审查的第 1 版判断/研究结论/文案/结构。
3. ATTACK：从至少两个独立视角挑战它，如真实目标用户、冷启动陌生访客、成熟交易者、怀疑型产品经理、转化分析师；必须指出具体可能失败的位置。
4. VERIFY：用现有源码、真实页面、竞品可观察事实、历史业务数据或新研究核对。无证据时写 HYPOTHESIS，不把角色模拟当成用户访谈。
5. REVISE：实际更新产物，留下与前版差异、为何改变；不能只写“已优化”。
6. CHECKPOINT：决定 PASS_WITH_ASSUMPTIONS / REVISIT / EVIDENCE_BLOCKED / NEED_USER_DECISION。
7. ROUTE：继续同节点新循环，或跳回另一个节点。不得因为表面上 G1/G2“已完成”而禁止回退。

至少进行一轮“草案→反对→修订→复核”；若仍出现重大矛盾继续迭代，直到当前任务可交付、证据限制已明确或确实必须由用户作决策。**不得无限自我重复**：新一轮必须带来新证据、修正具体缺陷或改变可检验预测。

## 分节点必须有的审查问题和产物

### D 需求循环
- 问的是“要做什么”还是“为何值得做”？
- 需求是否错误归因（例如把渠道质量问题归为设计问题）？
- 如果不做页面、仅修改渠道/入口/一句文案，会怎样？
- 一版之后至少提出“最强反对意见”与低成本替代。
- 产物：原始需求、重述后的问题、备选问题定义、反证、决策理由、仍缺的数据。

### R 研究循环
- 实际需要回答的 3–5 个研究问题是什么？
- 竞品被观察到的事实，是否真的支持我们给 EBC 的建议？
- 市场/用户/平台是否一致？信息是否过时？有没有反例？
- 一版研究结论后主动寻找反证和缺失样本，重写推荐。
- 产物：研究简报、来源矩阵、观察 vs 推断、证据冲突、对方案的影响。

### U 用户决策循环
- 用户在看到页面前为什么来？已经知道什么？害怕什么？有哪些替代选项？
- 初见 3–5 秒、第一轮滚动、CTA 点击前、跨域注册后可能怎么想？
- 至少包含“愿意继续、犹豫、误解/退出”三类路径，对方案提出具体改动。
- 产物：用户情境卡、意图假设、心理阻力、路径模拟、断点与修复假设。
- 模拟仅能产生设计假设，不是假装真实调研或声称预测转化率。

### C 文案循环
- 每条关键文案分别回答什么具体用户问题？有什么来源与约束？
- 多个切入角度（而不只是同义词）如何互相竞争？
- 经怀疑型访客、初学者、成熟交易者逆向阅读，哪里模糊、夸张、重复、没有新信息？
- 选出版本并实质性改写；文案改变需重新检查 U 与 S。
- 产物：主张结构、不同策略文案、逐条评论、修订稿、术语/事实检查、版本决策。

### S 方案循环
- 是否已有对应的候选或用户锁定 Page Structure？**先查历史类型，再按用户需求选择真实信息职责；只有无适用骨架或存在新问题时才提出结构性变化。**
- 是否存在真正不同的策略和用户行为路径？不等于强制结构上不同的屏数。
- 模块为何存在？为什么在这里？如果删除它会怎样？前后是否重复？
- 从高意向和低意向入口分别走一遍，重点验证跳出、疑虑、CTA/表单断点。
- 输出多方案比较，拒绝一个版本一把过；用本任务的成功目标选出更稳妥的方案。
- 产物：真正不同的策略 A/B（或解释为什么仅一种有意义）、模块职责、`CHOSEN / REJECTED / SACRIFICE / FAILURE CONDITION`、模拟反馈、实质修订与可视化实现契约。方法见 `pm/methods/page-logic-and-content-scope.md`、`pm/methods/decision-tradeoffs-and-correction.md`。

## 循环间的反向触发示例
- Research 发现竞品“0 成本”只是有条件优惠 → 回到 Demand 校验需求目标，回到 Copy 移除模糊承诺。
- User 模拟显示成熟交易者在 Hero 看不到交易规格 → Copy 重写卖点 → Strategy 调整顺序。
- Copy 无法在一行说清某卖点 → 回到 Research 找真实证据/产品解释，而非强迫设计把字缩小。
- Strategy 中两个模块重复 → 回到 User 确认具体顾虑是否真实 → 删除或重构模块。
- QA 发现表单目的地与广告承诺不符 → 回到 Strategy/Copy 修订，而不只是修按钮。

## 退出条件（用户不必亲自批每份中间文档）
五个节点都满足：核心问题有清晰定义；观察与推断分离；至少一次有效反驳和版本修订；用户路径可执行且不自相矛盾；没有已知重要错误；关键信息空缺标注并有最小化确认方案。

退出是“当前证据下可以进行下一步设计/编码”的判断，不是“方案已通过真实用户测试”。外部 A/B/访谈与行为数据应在后续持续更新置信度。

用户介入只用于：多种方案价值选择、产品真实状态、无法推断的重要业务决策、重大品牌方向；其他问题 Agent 自行研究并产出建议。

## 推理记录（可审计，不暴露隐藏思维）
每个节点输出简明的“可检查决策日志”，而不是内部推理过程：
- DECISION / VERSION / EVIDENCE / COUNTERARGUMENT / CHANGE / RESIDUAL_RISK / NEXT_ROUTE。
- 区分 OBSERVED / VERIFIED / HYPOTHESIS / COUNTERFACTUAL_SIMULATION / DECISION。
- 如果无法查证数据，清楚标记，不制造用户研究、眼动热图、CTR/CVR、成功概率。
- 主输出是可执行方案与关键依据，过程附录只记录关键修改，不制造冗余自我对话。

## 时间与深度分级
- QUICK（文案或小改动）：相关节点仍需至少 1 次严谨自审→修订，其他节点做必要影响检查。
- STANDARD（新的 LP/产品页）：D/R/U/C/S 五节点均至少完成 1 次循环；对冲突最多的节点追加研究和修订。
- DEEP（战略改版/大投放）：多方案、多用户情境、深入竞品、可用数据与推演、二轮以上证据挑战。
深度影响研究范围，不允许 QUICK 退化为“直接输出第一稿”。

## 价值优先级与最低合规底线
优先级：用户问题与心理理解 > 研究真实性 > 文案质量 > 页面策略与转化路径 > 视觉和工程的实现效率。
第一期不建立冗长合规审批引擎，但最低要求：EBC/合作品牌与监管名称、所属实体、产品性质和状态写对；不编造收益、费率或授权；必要风险披露不能为了视觉或广告过审被隐藏。发布前仍按适用真实监管和公司流程执行，不以“简化第一期”替代合法上线审查。
