## 1. 典型归因链路
广告链接 → LP URL（BID/linkCode/source/语言等）→ CTA → 注册入口 → CRM 接收与记录 → Lead/客户归属。
跨域跳转需要保留业务要求的参数；光检查 LP 地址不够，要核对目标 URL、注册成功 URL 与 CRM/SF 记录。

## 2. 历史 CRM 入口（仅供核对，不自动生成生产 CTA）
源资料记录 `crm.ebccn.cn/signup` 与 `crm.ebccn.cn/signin` 为某类访问的统一入口，并按 PC/移动端路由到不同的 CRM 页面。
历史描述：PC 注册与登录使用 `/signup` 和 `/signin`，移动端可能转为 `/pages/login/signup` 和 `/pages/login/signin`。
不能推断所有市场都应使用这套路径；本项目发布前由系统负责人确认。

## 3. 参数
- `bid`：历史资料中为不同推广组配置的营销参数；**不能直接复制历史数字到新活动**。
- `IBID / linkCode`：资料指出部分 IB 链接需要使用包含账户类型尾缀的完整 linkCode；仅用 IBID 可能丢失归属。
- `source`、UTM、语言参数：根据渠道、页面和 CRM 的真实规则配置；不得任意删除或改名。
- 不带 bid 的来源显示方式、adset name 字段等可能依赖某版本实现，须在实际工程核验。

## 4. IP 与 URL 语言优先级（历史描述）
1. URL 已指定语言路径时，优先采用该语言，不应无条件覆盖。
2. URL 无语言时是否启用 IP 自动跳转由页面配置决定。
3. 资料中的实现基于国家列表接口与 mccCode 映射。
4. 找不到对应语言时使用默认英语的历史逻辑；是否继续采用由当前站点明确批准。
5. 切换区域/语言时需验证参数、URL、表单目的地和缺失页面的 fallback，不应出现 404 或错误实体。

## 5. 测试矩阵
| 变量 | 示例 | 必须验证 |
|---|---|---|
| 设备 | PC、Mobile | CTA / 表单 / 路由可用 |
| URL 语言 | 有/无语言路径 | 手动选择优先级 / fallback |
| IP 地区 | 允许/受限/无法识别 | 页面可用性 / 适用营销披露 |
| 来源参数 | BID、linkCode、source、UTM | LP → 注册 → CRM 字段保持 |
| 注册用户状态 | 新用户/已有用户/失败 | 登陆/注册目的地与反馈 |
| 页面版本 | 多语种与 A/B | 同一事实、不同版本的链接与数据口径 |

## 6. 合规与安全
历史资料中存在特定市场“去掉 CFD 词语”等投放经验；**不能转成自动化投放规则**。需要真实、清楚且适用的披露，由 Compliance/法务与广告平台政策共同约束；不得因广告拒审而隐藏重要性质或风险。
不要在规则库内存储可用凭证、API Key、客户信息、未审批的监管声明。

## 7. 更新责任
此文件只记录当前历史材料，正式路由与归因配置应由 IT、CRM 和市场渠道负责人维护一份有版本的 `business_config`。AI 生成项目不能自动视历史示例为最新值。
