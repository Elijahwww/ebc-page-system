# LP 转化诊断方法 · v0.2

> 状态：RULE_CANDIDATE / OBSERVED_FROM_INTERNAL_CASE
> 来源：《MAR-Landing Page Knowledge Base-111126-094756.pdf》第 5–8 页。
> 非真实业务决策结论：以下是研究方法与历史样本观察，不足以证明某视觉方案胜出。

## 原则：先拆“流量 → 页面 → 后端”，再决定改版
低转化率不等于页面文案或 UI 必然有问题。按以下层次调查：

### Layer A — 流量与受众
按市场、广告平台、渠道、关键词/创意、Generic/Remarketing/Similar、设备、语言和页面版本拆开。先查流量意图是否与页面目标匹配。不可直接混合比较不同地区或不同流量类型的 LP 总转化。

### Layer B — 广告承接
用户从广告获得什么预期？LP 首屏是否解释同一产品与主要利益？广告承诺是否在页面中被合理准确地实现？CTA 是否明确且与广告一致？

### Layer C — 页面使用
查看首屏理解、关键模块曝光、停留与互动、CTA、表单启动和提交、移动性能、错误和掉链。页面问题要分内容、视觉、操作、加载、设备，不宜只以跳出率推断。

### Layer D — 归因与 CRM/后端
注册/Lead 来源是否正确记录？是否能定位跨域或语言跳转后丢参数？注册后的 KYC、MT 开户、FTD、客户跟进状态是否影响业务结果？PM 不应把跟进能力问题全部归因为 LP 设计问题。

### Layer E — 实验与复盘
提出清楚假设，记录主要变化、渠道/受众定义、样本、日期与排除条件；可能时通过 A/B 测试验证，避免同一时间改变过多变量导致因果不清。

## ETF 历史观察（2026-07-01 至 2026-08-10，另有 08-12 后端数据）
原文报告观察：
- 印尼 ETF-a 页面互动与注册/KYC/FTD 数量高于当地 ETF-c，但是否因为渠道/流量差异，现有摘要不能证明设计因果。
- 泰国 ETF-c 搜索流量互动显著低于再营销流量；不能据此推定同一个页面的内容单独导致差异。
- 某些市场页面互动不错，后端 KYC/FTD 却弱；单凭页面停留无法判断业务质量。
- 注册后的部分客户未联系、跟进次数不足或状态未标记。后端客户管理可能是转化的瓶颈之一。
- 数据有效期、跟踪口径、受众和样本量有限；不得将结论提升为永久“最佳页”规则。

## 交付格式
1. 问题：什么指标/市场/时间发生变化？
2. 数据完整性：埋点、漏斗、归因、流量质量可信度。
3. 假设树：流量问题 / 广告承接 / 页面 / 注册与追踪 / 后端跟进。
4. 证据：逐项数据来源、观察时间、对照限制。
5. 优先实验：预期影响、改动范围、实验门禁与风险。
6. 复盘：证实/未证实/样本不足；新的规则仍为 RULE_CANDIDATE，待真实评审。

## 禁止推断
- “用户停留高＝用户喜欢页面＝产生高质量收入”。
- “旧 ETF-a 领先＝所有市场都应该使用 A 版”。
- “所有低注册问题都可以通过 Hero/按钮改动解决”。
