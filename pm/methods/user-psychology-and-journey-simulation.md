# 用户心理与路径推演工作台 v1.0

状态：METHOD_CANDIDATE。用途：将营销策略从“公司想讲什么”切换到“用户为什么看、如何理解、何处怀疑、何时愿意行动”。
重要：模型模拟是 COUNTERFACTUAL / HYPOTHESIS，不是真实访谈、眼动结果、点击热图或转化预测。

## 外部页面证据升级
如现有 EBC 受众/路径案例不足，应调用共享 Reference Discovery（研究分支 `assets/reference-intelligence-v0-1`）；逐层分析直接同行 → 大金融 → 头部科技 **相同用户任务** 的 Hero 信息、首次滚动、证明、CTA/申请/注册步骤。须区分真实网页观察与模拟心理；没有浏览器截图不能推断真实首屏视觉权重。外部证据应改变一次 U 情境/失败路径，并回流 C/S。

## 市场与工作语言不能混为一谈
用户心理与路径的目标市场来自项目 Brief，而不是中文文案。普通项目以中文形成用户情境假设；明确 Japan 等本地专属页面时，必须先查当地用户、渠道、产品认知及可靠参考，且保留来源/限制，不能把中国市场的搜索/社媒/支付习惯当作默认。当地差异通过 `localization/chinese-first-and-market-overrides.md` 管理，除特定差异外沿用通用路径分析方法。

## 一、先分辨用户并非同一种“小白 vs 专业”
最少用 2–3 个**与项目相关且不同意图**的情境，不强制同一套 Personas：
- 初次接触型：搜索问题尚不明确、对 CFD 交易机制知之甚少。
- 类别认知型：知道 ETF/原油/跟单是什么，比较选择与风险。
- 高意向型：想查看标的、费用、执行指标、最低手数、注册入口。
- 品牌验证型：怀疑该网址是否 EBC 官方、监管与合作信息是否可靠。
- 来源错配型：点击广告后发现不是预期中的股票/ETF 持有或其他投资产品。
不能凭空为这些人填年龄、收入、地区、学历；没有数据时保留角色为“情境假设”。

## 二、用户心理分析维度（不是给用户贴偏见标签）
| 层次 | 必须回答 | 常见的错误 |
|---|---|---|
| Trigger | 为什么现在会遇到这个页面？查询/广告/朋友推荐/已有账户？ | 假定所有人都准备开户 |
| Motivation | 想达成什么结果：理解、比较、验证、开户、尝试？ | 把产品卖点当作用户目标 |
| Prior knowledge | 已经了解哪些概念，尚不知道什么？ | 用手数/杠杆直接吓退新用户 |
| Expectations | 用户期待产品是什么，CTA 后会去哪？ | 不解释 CFD 与实际持有的区别 |
| Friction | 认知成本、信任、术语、行动、隐私、时间 | 只考虑 UI 按钮大小 |
| Perceived risk | 会不会亏损、收费、失去控制、被欺骗？有何事实支持？ | 用“更简单”“稳赚”掩盖不确定性 |
| Credibility | 哪类证据会让该用户相信这条主张？ | 滥用 logo、奖项、历史收益数字 |
| Alternatives | 不行动、继续搜索、选择不同平台/产品 | 误以为没有竞争路径 |
| Decision trigger | 什么信息足够支持下一步？ | 把点击 CTA 当作信任形成的证据 |

注意：用户心理不是“如何利用偏见强迫转化”。目的应是提升真实理解、适配与选择，不用恐惧/FOMO/虚假紧迫感诱导金融决策。

## 三、必须走完的路径模拟矩阵
每个典型用户情境至少沿关键触点推演：
1. PRE-ENTRY：用户刚从什么入口/广告承诺而来？
2. 0–5s：一眼看到什么，会认为 EBC 在提供什么？是否误读？
3. FIRST SCROLL：为什么继续？第一个疑问是否有答案？
4. EVIDENCE：哪个陈述需要可信证据，是否理解“数字/条件/限制”？
5. DECISION：当前是立即点击、继续比较、离开，还是需要明确解释？
6. CTA CLICK：按钮名、目的地、跨域安全感、表单/登录状态？
7. AFTER ACTION：注册/留资之后发生什么，若失败/返回/中断如何处理？

每一行记录：触发 → 当前认知/疑虑 → 页面提供的信息 → 可能动作 → 失败模式 → 建议改动 → 验证方法。

## 四、至少三个路线（鼓励变体但不是生造用户数据）
A. HAPPY PATH（用户理解并愿意行动）：哪里仍可能误导或丢失用户？
B. HESITATION PATH（用户有兴趣但不信/不理解）：真正阻碍是什么，某条证据能否解决？
C. WRONG-EXPECTATION / EXIT PATH（广告或词义误导）：用户以为在买 ETF 份额、进入后发现 CFD；需要怎样准确而清楚地说明，甚至不应引导其开户？

有真实异常日志/转化数据时，先走数据证据路径，再用推演解释为什么可能发生。

## 五、反向评审循环
U1 依据研究建立用户情境与初始旅程；
U2 用“最怀疑的合理访客”质疑：为什么相信？为什么现在？为什么要留下邮箱？为什么不去找别家？
U3 用“不同行业认知水平的访客”复核术语密度、价值表达、数字单位、广告承诺；
U4 明确 3–5 个真正可能导致放弃或误解的节点；
U5 修改 Copy 或 Strategy，重新从用户入口走一遍，确认是否改善模拟矛盾；
U6 标注无法靠模拟解决的假设，需要真实研究或试验。

不得只输出“用户注重安全和收益”这种无法指导模块排序的结论。

## 六、例子（教学性示例，不代表真实用户反馈）
需求：“面向泛搜索流量推广 ETF CFD”。
- 假设情境：访客搜索“ETF 怎么买”期待持有真实基金份额。
- 初稿：Hero“一键购买全球 ETF”＋按钮“立即投资”。
- 反驳：实际服务是 ETF CFD；初稿可能造成对所有权/产品性质的错误预期。
- 修订假设：首屏直接写清“ETF CFD”，用简洁的机制说明解决疑虑；对已具备 CFD 认知的用户，前移平台/合约信息。
- 回流节点：Copy 修改 Hero；Strategy 调整机制说明优先级；Research 查询真实搜索意图和市场匹配度。
这个案例证明了**为什么要推演**，但不证明某版文案能提升转化。

## 七、退出标准
- 每类情境用户的第一核心问题、最大疑虑、继续/离开条件可见；
- 至少一条路径发现了原方案的真实逻辑漏洞并提出修改；
- 关键失败路径与 CTA 的后续体验被模拟；
- 心理分析和 Copy/Strategy 有至少一处可追溯联动；
- 已标记用户研究缺口，没有伪装“AI 预测了用户行为”。
