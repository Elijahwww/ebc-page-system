# PM 页面阶段门禁检查表 v0.2

> 状态：RULE_CANDIDATE；来源：产品部门检查清单、推广页日常经验总结、两张流程图（2026-11-11）。
> 使用方式：每项记录 `YES / NO / N-A / TO_CONFIRM` + 证据 URL/截图/工单链接 + Owner。若 `NO` 标明阻断级别；若 `N-A` 写明原因。不是所有页面都需要全部模块。

## G1 — 需求立项（PM）
- [ ] 页面目标与衡量方式明确（品牌 / 产品理解 / 合格 Leads / 活动参与）
- [ ] 目标用户及流量来源明确（国家、受众、推广渠道、搜索/再营销等）
- [ ] 目标语言、上线窗口和页面类型已确定
- [ ] 对应业务实体、区域投放限制与合规审核需求已列明
- [ ] SEO、域名/路由、统计和跨系统依赖已收集
- [ ] 已在适用项目管理系统记录需求与变更（实际 Jira SOP 待确认）
- [ ] 缺失数据和阻塞责任人明确

## G2 — 方案与文案（PM/Content/Compliance）
- [ ] 页面结构、用户从进入到最终行动的路径清楚
- [ ] 每个模块有单独信息职责，内容长度与受众/渠道相称
- [ ] 主 CTA/次 CTA、目标链接和目标动作明确
- [ ] 专业/产品/数字事实来源与适用范围已核验；市场限制已覆盖
- [ ] 风险及法务必需信息已按对应司法管辖区审批
- [ ] 需要多语言时，正式内容源与翻译范围已锁定
- [ ] 文案及结构已由相应负责人确认，进入正式设计；快速概念 Demo 另标记 EXPLORE

## G3 — UI/交互（Design + PM）
- [ ] 首屏信息优先级和视觉基调已确认
- [ ] 栅格、间距、文字/背景对比、焦点态与 Hover/Active 状态可检查
- [ ] Mobile、Desktop 及适用断点已覆盖
- [ ] 多语言/长文本的布局适配已检查
- [ ] CTA 可发现，表单与操作反馈清晰
- [ ] 视觉修改不牺牲信息理解与转化路径
- [ ] 待替换图片、数据及合规文字明确标记，不伪装已完成

## G4 — 本地化与开发（Localization/IT）
- [ ] 文案、翻译表和设计文件引用同一已批准版本
- [ ] 译文及小语种显示经过必要检查
- [ ] 路由/域名、注册/登录/Portal 域名和回跳行为按项目最新配置确认
- [ ] 表单字段、国家选择、验证规则、CRM/Lead 去向明确
- [ ] BID/linkCode、UTM、source 等参数的透传规则已按项目确认
- [ ] GA/GTM/Matomo 等按站点和渠道的要求配置，不重复错误植入
- [ ] SEO H1、标题、可索引内容、ALT、结构化数据（适用时）和链接已检查
- [ ] 代码与素材完成必要敏感信息及依赖检查，禁止私密长期 Token 暴露

## G5 — 上线验收（QA + PM）
- [ ] 访问/加载、布局、图片视频、无明显错位与异常
- [ ] CTA、弹窗、表单、注册、登录、KYC 或 APP 跳转（适用时）可用
- [ ] 地区/IP/URL 语言优先级及缺失语言 fallback 已验证
- [ ] 广告来源与注册来源在 LP → CRM 链路可追溯（适用于推广页）
- [ ] GA/GTM/Matomo 事件真实触发，口径和 Consent 约束已确认
- [ ] 风险提示、市场实体及重要金融文案符合获批文本
- [ ] 测试发现的阻断问题已解决，有证据、Owner 和结果
- [ ] 性能阈值根据当前产品要求批准；历史“首屏 2–4 秒”仅为待核验参考

## G6 — 上线后数据与迭代（PM/SEM/运营）
- [ ] 关键指标事件定义和统计窗口一致
- [ ] 分市场、受众、渠道及页面版本分析，避免混合流量导致误判
- [ ] 检查广告信息 → 首屏内容的一致性
- [ ] 拆分访问互动、表单、注册、KYC 和 FTD；不只看注册数
- [ ] 若转化低，先检查流量匹配/技术归因/后端跟进，再归因页面
- [ ] A/B 测试记录单变量/主要变化、样本与实验局限
- [ ] 关键问题进入 issue/决策记录，规则变更走 PR 审核

## Blocking 类别
- `P0_SECURITY_OR_COMPLIANCE`：密钥泄露、错误实体/禁投信息、误导性营销主张或关键法律风险 → 禁止上线。
- `P1_FUNCTIONAL`：CTA/注册/归因断链、关键错误展示等 → 需修复与复测。
- `P2_USABILITY`：影响理解或操作的响应式/翻译/视觉问题 → 依据具体情况评审。
- `P3_POLISH`：不影响事实/理解/操作的微调 → 可延期，不阻断交付。
