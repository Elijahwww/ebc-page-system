# EBC 页面：中文主稿优先与地区化例外规则 v0.1

> 状态：USER_CONFIRMED_WORKFLOW（2026-11-12 用户明确确认流程；非公司全市场合规 SOP）
> 一句话：**中文是默认的工作与审稿语言，不等于默认面向中国市场；翻译是中文文案获确认后的独立本地化任务，不等于逐字直译。**

## 1. 默认场景：中文优先（CHINESE_SOURCE_FIRST）
- 不论最终网站是否多语种，PM 需求诊断、行业/用户调研、方案推演、模块职责与核心文案**默认用中文**执行和审查。
- 按 PM 五节点 D/R/U/C/S 的独立循环产出中文工作方案与 `Copy Sheet zh-CN`；**中文主稿确认之前不启动大规模正式翻译或逐语言改稿**。
- 中文主稿确定后，将 Copy ID、版本号、产品事实/数字/CTA、具体使用场景与不可改变语义交给独立 Localization 阶段；目标语种由当期翻译人员/Agent 处理翻译、语义再创作与语言复核。
- 翻译不是逐字转换，允许按目标语言表达自然度调整句法、长度、词序、语气或文化隐喻；**不可悄悄改变获批的产品事实、用户行动目标、承诺、重要限定、信息职责**。若改写影响原意，返回 PM/Copy 处理。
- 缺术语库、缺目标语种终稿不应阻塞**中文** PM 方案、中文设计、中文交互 Demo 和组件化实现；跨语种上线与当地文案验证是后续独立任务。
- 本文件不强迫 Agent 为每一个中文稿提前制作多语言版本，也不要求中文标题按未知语言的最长译文缩短。

## 2. 明确区别：工作语言 ≠ 市场
- `working_language = zh-CN` 是默认的内部需求沟通和文案审稿语言。
- `target_market`、`audience`、`acquisition_channel`、`product_entity` 是独立变量，必须按真实项目 Brief 判断。
- 例如“面向日本市场的活动 LP”，即使先用中文写内部方案，**也必须先研究日本当地的用户、渠道、金融概念认知、活动习惯与可用依据**，而不是先写中国市场心理/场景再翻译成日语。
- 不以中国地区熟悉的平台、金融交易文化、消费预期或监管语境代表其他市场。跨地区可迁移的产品事实和通用交互可以复用，但“用户为什么关心、最先看什么、怎样信任、行动前需知道什么”必须在该市场重新检验。

## 3. 哪些默认共享，哪些需要地区化？
| 层面 | 通用默认 | 明确地区化需求时 |
|---|---|---|
| PM D/R/U/S | EBC 共用的需求挑战、来源研究和反向用户推演方法 | 当地行业竞品、用户意图、触点、渠道、文化/产品认知加入假设和证据 |
| Copy | 先按中文确认产品意思、信息职责和决策逻辑 | 同一意思在目标语言做**本地化改写**，不是中文逐字翻译；地区特定活动可在中文阶段先设计当地话语任务 |
| Design | 共用页面组件、栅格、布局规律、交互和 EBC 品牌基线 | 仅对真正有影响的文字扩展、字符字体、当地视觉偏好、支付/表单习惯、活动文化/素材等作适用例外 |
| Dev | 组件化、响应式、语义结构、状态与性能目标共用 | 按需支持 locale 资源、RTL/文字断行/字体回退、地区特有流程，不为每种语言独立重建页面 |
| QA | 中文主稿的逻辑与功能完整性先验收 | 真正需要交付该语种时增加术语、语义回译、地区适用、长文/排版/流转测试 |

**原则：先复用真正通用的约束，再对有证据的本地差异做小范围 Override；不因为存在多语言就提前重造全部内容或设计。**

## 4. 市场触发与路由
- `GLOBAL_DEFAULT`：仅指定普通官网/品牌/产品/推广页，无地区特殊要求 → 中文 PM / Copy 先定稿 → 共用 Design / Dev → 需要时本地化。
- `LOCAL_MARKET_SPECIFIC`：明确国家/地区、本地渠道、活动、监管实体或文化场景不同 → **在 PM Research/User/Strategy 起点**先读取该地区规范与外部市场案例，再写中文内部方案；涉及当地文案目标时提前记录变体需要。
- `LOCALE_COPY_REQUEST`：已确认中文 Copy Sheet 进入正式翻译 → 读取正式术语库和该 locale 的翻译/文风指南；译后核对语义与 CTA，不能以文案质量评审的“通过”替代本地翻译 QA。
- `LOCAL_DESIGN_EXCEPTION`：目标市场确有明显视觉/图文/文化/交互差异 → 写项目级 Design Override（说明证据、影响模块、改动边界），只修改受影响部分。
- `UNSPECIFIED_MARKET`：未说明地区时，中文内部表达不等于推定中国大陆投放；必要市场事实标 UNKNOWN，默认用较中性叙事先推进。

## 5. 日本地区活动页示例（逻辑演示，非已验证日本用户研究）
输入：“为 EBC 日本市场策划交易活动落地页。”
1. PM 仍用**中文**写 Brief、研究摘要、用户假设和首轮文案供内部审查；标注 `target_market=Japan`。
2. 在 R/U 节点先找日本本地 CFD/金融服务同类活动、日文官方产品解释、当地受众预期，必要时再扩展到大金融和日本当地优秀跨行业活动页。
3. 独立检查：活动资格/参与动机/真实渠道/页面顺序/用户路径是否符合当地场景，不能搬用中国市场春节/红包/微信群/CTA 习惯作为默认。
4. 中文版先确认页面的信息任务和利益/条件/下一步；若涉及日本特有的活动设计，在中文阶段就做好内容结构决策。
5. 进入日文 Localization 阶段再按照真实日文术语库和市场文风改写，完成当地语言、产品称谓和 UI 长文本 QA；只对必要视觉要素调整样式，不重做通用布局。
6. 缺可用的当地规范时，Agent 自主执行外部逐级研究并将结论标成 `LOCAL_MARKET_HYPOTHESIS`，不得声称已获当地正式验证。

## 6. Agent 出口与状态
默认输出：
- 中文 PM Decision Packet（含实际 target_market，不偷换为 China）
- 中文 Content / Copy Sheet（确认状态、Copy IDs、语义不可变条件）
- Design / Demo（通常以中文版为当前审查对象）
- `LOCALIZATION_PENDING`：只有项目要翻译时才进入独立步骤
- `MARKET_OVERRIDE`：仅在真实地区特殊要求时生成，写明来源、理由、适用范围
- 多语种正式上线前：术语/表达与功能/语境 QA 均需按目标市场完成。

## 7. 防止系统误读
- ❌ “只要是中文稿，就是给中国大陆用户看。”
- ❌ “文案写完立刻并行翻译 14 种语言，免得阻塞设计。”
- ❌ “直接把中文标题直译成英语/日语，原来是四字就译成四词。”
- ❌ “日本市场直接采用中国搜索用户心理模型，然后把页面语言改成日本语。”
- ❌ “没有日文稿时，不能做中文方案或中文 Demo。”
- ❌ “每个不同市场都要从零重写 Apple-style 设计系统。”
- ✅ “中文先形成经审查的语义主稿；地区市场从策略起点独立研究；翻译独立本地化；页面和组件尽量共享，必要时局部适配。”
